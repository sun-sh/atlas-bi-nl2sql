# 用户体验检查（2026-10-27）

本轮检查覆盖分析会话、经营总览、检索证据、评测和模型配置页面。重点是从提问到读取回答、追问、恢复历史的连续使用体验。

## 本轮已调整

| 用户遇到的问题 | 调整后的行为 |
| --- | --- |
| 历史、上下文与回答同时占据三栏，主任务不突出 | 聊天为主区域，历史会话与分析条件按需打开 |
| 旧布局规则使桌面聊天记录仅剩约 29px，窄屏输入框超出视口 | 固定视口内布局，聊天记录独立滚动，输入框保持可见 |
| 用户问题与模型回答混在一张报表卡里 | 问题靠右显示，AI 回答使用独立身份和内容区域 |
| 流式更新强制滚动，打断阅读前文 | 用户操作聊天记录后暂停跟随，提供回到最新回答按钮 |
| 查询完成清空用户期间写好的下一问 | 仅清除本次发送的问题，保留新草稿 |
| 中文输入法确认候选词时可能发送 | 忽略输入法组合状态下的 Enter，Shift+Enter 换行 |
| 生成期间切换会话或新建会话可能覆盖回复 | 生成时保护当前会话，禁用相关入口 |
| 查询失败只短暂弹出提示 | 错误留在当前回复中，可恢复原问题再试；已有结果在中断时保留 |
| SQL、明细、轨迹占据多个入口 | 统一收进数据依据与 SQL，按需查看 |
| 单个汇总数值也生成分类柱状图 | 仅在存在分类维度和多条结果时显示对比图 |
| 图表只展示前 8 项而缺少提示，明细只显示前 30 行 | 图表标明前 8 项，明细展示接口返回的所有行，查询截断时注明 |
| 数值 0 在部分文案及单元格中消失 | 转义时保留 0 和 false |
| 规则回退被显示成模型生成 | 按实际 SQL 来源展示标签 |
| 页面默认 Qwen 文案造成配置是否生效的疑惑 | 页面状态从当前运行配置读取，历史回复显示自身模型来源 |
| 演示数据的本月含义不清楚 | 标明数据范围和相对时间基准 2026-02-28 |
| 进入评测页即运行模型评测 | 改为点击后运行，提前说明需要模型调用 |
| 模型页重复标题占用高度，窄屏缺少导航 | 合并标题、压缩重复说明，增加窄屏导航，页面内容内部滚动 |

## 验证范围

- 自动化测试：81 项通过；JavaScript 语法检查通过。
- 浏览器检查：1440、1280、768、390px 四种宽度，覆盖五个页面；未发现文档横向或纵向溢出，聊天输入框位于视口内。其他页面长内容保留页面区域内部滚动。
- 10 项隔离交互回归：输入法、换行、会话保护、阶段原位更新、来源与零值、滚动、草稿、错误恢复、抽屉和评测入口。
- 人工检查桌面和窄屏截图，确认对话与模型表单可读。
- 本轮另行保留了 18 条 strict-model-v2 旧版真实模型黄金评测：5/18 通过；随后使用当前配置模型完成 strict-model-v3-100 真实在线评测：100/100 通过。模型评测成绩与前端交互验证分开记录。

## 产品上仍需进一步完善

1. **分析能力边界。** 当前演示使用固定数据、固定工作流与结构化意图规划，复杂自定义问题的理解、SQL 口径与结论质量仍需真实模型用例验收。
2. **图表语义。** 当前为基础分组比较；日期趋势、负数、占比、不同单位等还需要专门图形和格式化策略。
3. **模型配置过程。** 当前运行状态与编辑表单已区分；未保存修改提醒、跨服务商切换时的密钥使用提示可以进一步完善。
4. **长期工作流。** 会话限 7 天、20 轮；重要结果导出、主动保存与更长期检索尚未提供。
5. **评测结果留存。** 本轮只取消导航触发评测；跨刷新恢复上次评测、后台运行与进度仍有改进空间。

这里记录的是本轮确认的体验改动和剩余范围，不代表完整生产可用性验收。
